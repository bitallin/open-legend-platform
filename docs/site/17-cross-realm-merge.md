# 17 · 跨服、合区与多区

多区与合区是现有工程能力。跨服对战、通区后台、跨服变量没有协议。完成度不要把跨服写成矩阵里的 Done。多区启动方式以仓库 README 和 `scripts/create-realm.sh` 为准。

## 概述与玩家体验

运营可以同时开多个区，每个区是独立 Host 进程、独立端口和独立数据库。登录器列出这些区，玩家选一个进入。角色、行会、邮件都留在该区。

合区是停服工具：把两个 Sqlite 库合成一个，账号按用户名合并，角色重名加后缀，行会重名加后缀。它不是在线跨服。

跨服是未来能力：多个区的玩家进入同一张战场，打完回到原区，奖励写回原区。在该能力落地前，客户端区服列表里的每一行只连接一个端口。

## 协议 / MsgId

已有、用于选区的报文：

| MsgId | 消息 | 说明 |
|-------|------|------|
| 1005 / 1006 | `RealmListReq` / `RealmListResp` | `RealmInfo` 含 id、名字、地址、端口、状态 |

登录器也可以不发 1005，而读 `launcher/config/realms.json`。游戏内若再拉一次列表，以 Host 根据 `realms/catalog.json` 返回的结果为准。本区端口是进程实际 `BoundPort`。

## 服务端模块与配置

区服文件：

- `realms/catalog.json` 列出 `realm-classic-01.json`、`realm-classic-02.json`
- 每个区 JSON 含 id、显示名、端口、数据库路径、manifest 路径等（以文件内字段为准）
- 开区：`scripts/create-realm.sh <id> [name] [port] [admin-port]`

Host 参数：`--realm-id`、`--realm-config`、`--realm-catalog`。两个区是两个进程，Admin 端口也不能冲突。

合区工具：`tools/Legend.Merge`，规则全文在 `tools/Legend.Merge/MERGE_RULES.md`。摘要：

| 对象 | 规则 |
|------|------|
| 账号 | 用户名大小写不敏感。目标已有则保留目标密码与 account_id，源角色并入 |
| 角色 | 重名改为 `{原名}_m`、`_m2`…；character_id 冲突则新 GUID，并改写行会成员 |
| 行会 | 重名同样加 `_m`。成员与会长 id 按映射改写。仓库与审计随行会走 |
| 邮件与禁言 | 迁入 |
| 好友、寄售、攻城 | 以目标区为准，源侧丢弃 |
| 支付订单 | 不合并 |

必须先 `--dry-run`。正式合区前停掉两个 Host，避免写入旧库。

## 客户端表现

- 登录器列表展示区名、状态、RTT（[01](01-account-login-launcher.md)）
- 游戏窗显示当前 `realm-id`（**A-03**）
- 不提供「跨服传送」按钮，直到有 MsgId

Unity 与 Playable 的启动参数相同：`--host --port --realm-id`。

## 登录器相关

登录器是多区的主入口。`realmListUrl` 可以指向一份只含公开字段的 JSON，供公网列表，与本地文件合并。不要在这份 JSON 放数据库路径或 Admin 令牌。

更新通道按客户端版本，不按区服分叉协议。各区可以挂不同 manifest，这是 Host 的启动参数，不是登录器热更。

## 配置热更与脚本钩子

`reload-pack` 只影响当前进程的版本包。它不会把一区的配置推到二区。两区要同时换表时，对每个 Admin 端口各调一次，或重启时改 manifest 路径。

没有合区脚本钩子。合区是离线工具。不要在 Lua 里遍历别的区的数据库。

## 非目标

- 不实现第三方跨服命令、跨服变量或跨服沙巴克脚本。
- 不合区进行中的在线进程。
- 不把源区寄售挂到目标区角色身上（当前规则是丢弃源区寄售，避免悬空 id）。

## 扩展路线

未来工作，未进入矩阵。

1. **跨服战场**。独立的短生命周期 Host，或原区进程中的隔离地图实例。玩家凭证由原区签名，战场只信任签名，不信任客户端传来的等级。结算消息回原区发邮件。MsgId **TBD**。
2. **跨服攻城**。参与区数量设上限（产品上可按 5 个区设计容量）。每个区派一个行会。占领结果写回各区邮件，不直接改他区行会库。在路由完成前，沿用单区 `siege.json`。
3. **通区**。运营查看多区在线与封禁的只读聚合页，放在 [21](21-ops-gm-deploy.md) 的 Admin 之前的独立工具。它不合并数据库。
4. **合区变量**。活动脚本若需要「已合区次数」，由合区工具写一行元数据进目标库，Lua 只读。不提供任意键值运算语言。
5. **角色转区**。与合区不同，是单角色迁移。要处理名字冲突和行会退出。未设计前拒绝「带号去别的区」。
