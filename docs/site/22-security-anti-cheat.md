# 22 · 安全与反外挂

本页只写服务端如何拒绝非法请求，以及登录器如何避免启动被篡改的文件。不写外挂制作、加速器、封包伪造或绕过检测的方法。

完成度：认证与封禁禁言已经在登录、聊天和 M19 中。矩阵 **H-08** 覆盖脏词与禁言。其余策略很多还是代码里的错误码，没有单独矩阵行。不要把「有错误码」写成反外挂系统 Done。

## 概述与玩家体验

正常玩家登录、移动、战斗、交易、支付时不会看到安全系统。异常时看到明确失败：版本不对、登录失败、移动被挡、点得太快、安全区不能打、金币不够、订单无效。

被封禁的账号无法登录。被禁言的账号无法发言。支付不到账就不会发货。

## 协议 / MsgId

安全相关的已有错误码（`protocol/legend_protocol.proto`）：

| 码 | 名称 | 何时 |
|----|------|------|
| 1001 | `ERR_VERSION_MISMATCH` | 握手版本主版本不兼容 |
| 1002 | `ERR_AUTH_FAILED` | 口令错误 |
| 1003 | `ERR_INVALID_TOKEN` | 会话无效 |
| 1006 | `ERR_RATE_LIMITED` | 请求过频 |
| 1015 | `ERR_SAFE_ZONE` | 安全区攻击 |
| 1073 | `ERR_MOVE_TOO_FAST` | 移动快于服务端间隔 |
| 1079 | `ERR_BANNED` | 封禁 |
| 1080 | `ERR_MUTED` | 禁言 |
| 1081–1083 | `ERR_PAYMENT_*` | 支付拒绝、无效、重复 |

所有玩法拒绝码（距离、冷却、权限）都是权威判定的一部分：客户端预判只为了手感，服务端否决时以回包为准。

没有独立的「反外挂心跳」MsgId。若要加完整性挑战，号段 **TBD**，并且只携带随机数与客户端版本，不在文档里设计可被仿造的通过条件细节。

## 服务端模块与配置

- 口令：`server/Legend.Storage/PasswordHasher.cs`。存哈希，不存明文
- 会话：`RedisSessionStore.cs` 或进程内会话。泄露的令牌应能随封禁或过期失效
- 封禁禁言：`ModerationStores.cs`，Admin 见 [21](21-ops-gm-deploy.md)
- 移动速度：`MoveReq` 处理与 `ERR_MOVE_TOO_FAST`
- 战斗合法性：距离、冷却、死亡、攻击模式、安全区，分布在 `GameWorldModule` 与 `PhaseMRules`
- 脏词：`version-packs/sample-classic/configs/profanity.txt`
- 支付验签：Mock HMAC、微信与支付宝提供方。回调金额必须等于订单 `PriceCents`
- 帧大小：`ProtocolConstants.MaxPayloadSize` 1MB。超长帧在网关拒绝，避免内存被单连接撑满
- Lua：硬沙箱，见 [18](18-script-config-hotreload.md)

速率限制的具体阈值以网关实现为准。文档要求：聊天、拾取、移动、交易锁定都要有上限；触发时返回 `ERR_RATE_LIMITED` 而不是断开整个区。调阈值时加测试，避免误伤正常连点吃药。

日志可以记角色 id、MsgId、错误码。不要记明文密码、支付密钥或完整证件号。

## 客户端表现

- 握手失败停在登录页并提示版本
- 封禁与禁言展示服务器返回的消息文本
- 本地加速动画不能连续发送超出间隔的 `MoveReq`；即便发送了，被拒绝后要把角色拉回 `MoveSync`
- 支付页不保存 `pay_payload` 里的敏感串到日志文件

Unity 与 Playable 使用同一错误码。不要在某一端把 `ERR_MOVE_TOO_FAST` 当成成功。

## 登录器相关

更新通道在替换客户端前校验清单里的大小与哈希（扩展，当前下载器仍是骨架，见 [01](01-account-login-launcher.md)）。哈希不符则不启动，并保留上一份可运行文件。

登录器不把区服列表里的地址当成可执行脚本来跑。`clientExecutable` 只能是配置里预期的游戏程序。

## 配置热更与脚本钩子

脏词表可热重载。封禁名单不在版本包里，热重载不能清掉封禁。

脚本不能关闭速率限制，也不能把某角色设为「免疫校验」。

## 验收标准

| 项 | 规格要点 |
|----|----------|
| A-02 | 错误口令失败，成功才发会话 |
| H-08 | 脏词替换、禁言、屏蔽 |
| M19 | ban 持久化，mute 拒聊 |
| C-13 / P-07 | 安全区不可攻击 |
| 1073 | 过快移动被拒并校正位置 |
| 1006 | 过频请求被拒 |
| 12 篇支付 | 签名与金额、幂等 |
| 帧上限 | 超过 1MB 的 payload 不进入业务模块 |

自动化从现有 `Legend.Tests` 与 verify 脚本覆盖。缺测试的项目在补规则时补测试，不在本文编造「已经检测了某外挂」。

## 非目标

- 不文档化、不实现外挂、封包重放步骤、内存修改或加速方法。
- 不承诺「能挡住所有辅助」。规格只要求权威状态在服务端。
- 不接入来源不明的反外挂驱动。若使用平台能力，单独评审权限与隐私。
- 不把第三方防刷说明抄进仓库。需要策略时在下面扩展里自研规则。

## 扩展路线

未来工作，未进入矩阵。

1. **登录与协议速率**。同一 IP 的注册、登录、握手失败次数上限，超限短暂拒绝。阈值放 Host 配置，不放版本包，避免被热更误改成 0。
2. **经济异常**。短时间金币增量超过配置则冻结交易与寄售，等待管理员。只冻结，不自动没收。规则用服务器账本，不用客户端上报的「我拾取了多少」。
3. **移动与技能采样**。记录拒绝次数，供 [21](21-ops-gm-deploy.md) 的审计查看。不对玩家公开算法参数。
4. **客户端完整性**。登录器哈希通过后，握手可以带构建号。服务端只拒绝过旧的 `protocolVersion`，不把构建号当作唯一信任根。
5. **实名与防沉迷**。见 [01](01-account-login-launcher.md)。时长限制在登录模块，不在战斗公式里。
6. **交易与仓库二次确认**。高价值物品（配置列表）锁定前提示。这是 UI，服务端仍然校验绑定与数量，见 [11](11-trade-stall-auction.md)。
