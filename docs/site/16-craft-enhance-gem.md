# 16 · 合成、强化与镶嵌

完成度以矩阵 **E-13、E-14** 为准。强化报文已有。打孔、宝石、合成、刀魂、投保没有 MsgId。

## 概述与玩家体验

玩家对已穿戴装备花费金币强化。成功则强化等级上升，攻击、防御或生命按物品上的 `enhance*PerLevel` 增加。失败规则以服务端当前实现为准：样例路径描述是花金币强化，没有单独的矿石消耗物品。客户端可以没有完整强化窗，但请求必须能从人物面板或调试入口发出才算可玩闭环（矩阵 E-13 的说明提到 UI 与矿石）。

套装是若干件同时穿戴时的额外加成（**E-14**）。件数不足不给套装属性。

合成与镶嵌是扩展：把材料收成新物品，或在装备上打开宝石孔。未落地前，材料只是 `kind=material` 的普通物品（如 `item_copper_coin`）。神器升级表在扩展路线，不复用装备强化等级。

## 协议 / MsgId

| MsgId | 消息 | 说明 |
|-------|------|------|
| 2305 / 2306 | `EnhanceEquipReq` / `EnhanceEquipResp` | 强化。拒绝 `ERR_ENHANCE_DENIED (1025)`、`ERR_NOT_ENOUGH_GOLD` |

鉴定 3931 与修理 3903 属于装备维护，规格在 [07](07-equipment-inventory.md)，不在强化成功率里重复扣耐久。

合成、打孔、镶嵌、拆卸、刀魂进度、投保开关：**TBD**。

强化等级存在装备实例上，脱下再穿保持等级。交易把物品交给对方时，等级跟着实例走，不能在交接时被客户端改写。

## 服务端模块与配置

- 处理在 `GameWorldModule` 的装备路径（`EnhanceEquip`）
- 物品字段：`enhanceAtkPerLevel`、`enhanceDefPerLevel`、`enhanceHpPerLevel`（`items.json`）
- 钩子：`on_enhance`（`scripts/equip.lua`）
- 套装：矩阵 E-14。若套装表已在代码或物品字段中，以该实现为准；版本包样例没有单独的 `sets.json`。在补文件之前，套装判定的 id 列表应集中在一处（建议未来 `configs/sets.json`），不要散落在客户端

费用曲线若写死在代码里，改费用必须改代码并测试。规格要求下一步把 `goldCostByLevel` 放进物品或全局强化配置，使 `reload-pack` 能调价。在此之前，文档不编造每一级的金币数。

损坏折半（耐久 0）发生在加成汇总之后，强化等级本身不因耐久清零。

## 客户端表现

- 人物面板展示强化等级与加成差值
- 没有矿石图标时，按钮文案写「花费金币强化」，避免玩家以为需要矿石
- 成功与失败都要有提示音或飘字（可复用 UI 点击音 **U-10**）
- 套装激活时在 Tips 列出已满足件数。Tips 数据来自物品模板，不来自自由文本脚本

Unity 与 Playable 共用 2305。只在一边做窗口时，另一边至少不要发送错误字段。

## 登录器相关

无。

## 配置热更与脚本钩子

`on_enhance` 在服务端判定成功或失败之后调用，用于公告稀有成功。脚本不能把失败改成功。

热重载改变 `enhanceAtkPerLevel` 后，已有强化等级按新倍率重算属性，不退金币。若新倍率更低，属于运营调表，登录时推一次属性相关的背包或外观刷新即可。

## 验收标准

| 矩阵 ID | 规格要点 |
|---------|----------|
| E-13 | `EnhanceEquip` 花金币提升强化等级，属性按每级字段增加。矿石不是当前消耗品 |
| E-14 | 套装件数满足时给额外属性，不足不给 |
| E-10 / E-11 | 耐久与修理不清除强化等级 |

## 非目标

- 不读取第三方合成脚本或宝石孔二进制。
- 客户端不掷强化成功率。若存在成功率，随机数在服务端。
- 不把强化做成无限叠加的客户端显示。

## 扩展路线

未来工作，未进入矩阵。

1. **矿石消耗**。`EnhanceEquip` 增加可选材料 `itemId` 与数量。金币与材料都够才尝试。失败是否掉级由配置 `failMode`：`none`、`drop_level`、`destroy`。默认保持现在的「只花金币」直到配置出现。
2. **合成**。`configs/craft.json`：配方 id、材料、产出、金币、NPC 限制。请求 MsgId **TBD**。一次只合成一份。材料不足 `ERR_ENHANCE_DENIED` 或新错误码，不要部分扣除。
3. **打孔与镶嵌**。装备实例增加 `sockets[]`。开孔消耗道具。物品模板写 `socketCountMax`，超过则拒绝开孔。宝石是 `kind=gem` 的物品，镶入后加成生效，拆下返回背包。宝石只用白名单 `statId`（与 [03](03-attributes-growth.md) 自定义属性同一名单），禁止脚本随手写属性名。
4. **刀魂**。独立进度条，满了换成固定技能加成 Buff。进度存在装备上。报文可与强化回包分字段，未分之前不要复用强化等级表示刀魂。
5. **投保**。标记 `insured=true` 的装备死亡不掉，或掉了进邮件。与 [03](03-attributes-growth.md) 的 `deathItemChancePercent` 叠加：先排除投保件，再在其余物品里掷骰。投保费用走 NPC。
6. **分解**。装备变材料，强化等级换额外材料数量。销毁前要客户端二次确认，服务端仍以请求为准。
7. **穿戴提示**。纯客户端：背包里出现更高加成且等级足够的装备时，角色按钮显示提示。判定用本地缓存的模板，服务端不推「你该换装」。
8. **神器升级**。`configs/artifacts.json`：`artifactItemId`、`level`、`materials`（材料 `itemId` 与数量）、`statBonuses`（白名单 `statId` 与数值）。槽位见 [07](07-equipment-inventory.md) 的 `kind=artifact`。神器等级存在神器实例自己的 `level` 上。**禁止**复用装备 `enhanceLevel` 表示神器等级。若需要失败规则，单独写 `failMode`，不要默默走强化失败。矩阵占位建议 `E-16` 与 07 相同，落地再写入矩阵，不计分。
